# 자체 BaaS 기반 전환

## 변경 요약

- 관리형 Supabase 앱 연결 계획을 웹사이트 빌더 전용 자체 백엔드로 전환했다.
- Fastify API, Better Auth 세션, 분리된 DB runtime 역할, PostgreSQL RLS actor 트랜잭션과 SQL migration 실행기를 추가했다.
- identity, workspace, project, draft revision, immutable release의 공급자 중립 PostgreSQL 기준선을 추가했다.
- workspace와 첫 project를 원자 생성하는 API와 RLS 프로젝트 목록 API를 추가했다.

## 수정된 파일

- `server/`: 설정, 인증, HTTP API, DB pool·identity·actor transaction·migration runner
- `db/migrations/`: 역할·인증 테이블·플랫폼/RLS SQL
- `tests/`: 서버 설정, API 인증 경계, transaction-local actor 검증
- `package.json`, `package-lock.json`: Fastify, Better Auth, PostgreSQL driver와 실행 명령
- `.env.example`: 자체 API·DB·Auth 환경 변수 경계
- `README.md`, `AGENTS.md`, `docs/`: 아키텍처 결정·진행 상태·보안 원칙

## 이유

브라우저에서 DB에 직접 접근하는 관리형 BaaS 계약 대신, API·배포·권한·결제·도메인까지 같은 서비스 경계에서 소유하기 위해서다. 인증 암호학은 검증된 라이브러리를 사용하고 사용자별 데이터 격리는 PostgreSQL RLS로 계속 방어한다.

## 영향

- 기존 React/Vite 02B 화면과 Local CMS 동작은 변경하지 않는다.
- 기존 `supabase/` migration과 47개 pgTAP 테스트는 전환 검증 기준으로 보존한다.
- 새 `db/migrations/`는 깨끗한 PostgreSQL 17 적용과 재실행을 검증했지만 운영 가능으로 판단하려면 React·CMS·미디어·복구 검증이 더 필요하다.
- React 로그인·CMS 저장·미디어는 아직 새 API에 연결되지 않았다.

## 검증 결과

- `npm test`: 47/47 통과
- `npm run build`: 통과
- `npm audit --omit=dev`: 취약점 0
- `node --check server/**/*.js`: 통과
- 실제 PostgreSQL 17 통합: 4/4 통과 — unsafe 역할·membership 거부, advisory-lock migration 재실행, Better Auth cookie, 두 사용자 격리, disabled/soft-delete 차단, runtime 분리·비소유·BYPASSRLS 금지
- 통합 테스트용 PostgreSQL 컨테이너와 `postgres:17-alpine` 이미지는 검증 후 제거
