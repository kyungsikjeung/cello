# 백엔드 운영 경계 리팩토링과 브랜치 운영 문서

## 변경 요약

- 외부 `Host`·forwarded 헤더가 Better Auth 요청 기준 URL을 바꾸지 못하도록 고정했습니다.
- API runtime, migration, DB role provisioning 환경변수 계약을 분리했습니다.
- 서버 시작 실패와 `SIGINT`·`SIGTERM`에서 Fastify와 DB pool을 한 번만 정리하는 수명주기를 추가했습니다.
- workspace/project HTTP route에서 사용 사례와 SQL을 service·repository로 분리했습니다.
- 예상 가능한 DB 오류를 안정된 API 오류 코드로 변환하고 예상하지 못한 500만 error 로그로 기록합니다.
- `main` README의 브랜치 표를 실제 브랜치만 남기도록 축약하고 PR 중심 운영 방식을 명시했습니다.

## 수정된 파일

- `server/auth/routes.js`: canonical Auth URL과 전달 헤더 경계
- `server/config.js`: runtime·migration·provisioning 설정 로더
- `server/.env.runtime.example`, `server/.env.admin.example`: API와 관리자 작업의 환경파일 분리
- `server/runtime.js`, `server/index.js`: 시작·종료 수명주기
- `server/errors.js`: 공통 API 오류 계약
- `server/services/platform.js`: workspace/project 사용 사례
- `server/db/platform-repository.js`: 플랫폼 SQL
- `server/db/with-actor.js`: 변경 불가능한 `app_runtime` 역할 적용
- `server/scripts/migrate.js`, `server/scripts/provision.js`: 연결·rollback·pool 정리 강화
- `tests/backend/`: 설정·Host·오류·수명주기 회귀 테스트 추가
- `server/README.md`, `docs/SELF_HOSTED_BACKEND.md`: 백엔드 브랜치 목적과 실행·보안 경계
- `README.md`: 핵심 브랜치 목적, `main` 운영 방식과 최신 검증 수치

## 이유

API와 관리자 작업이 같은 설정 계약을 사용하면 migration 관리자 URL이 runtime에 섞일 수 있고, 외부 Host 헤더나 비정상 종료는 인증 기준 URL과 DB 연결 정리에 영향을 줄 수 있습니다. 다음 CMS 저장 API를 추가하기 전에 HTTP·사용 사례·SQL·오류 책임을 최소 단위로 분리했습니다.

## 영향

- API 경로와 PostgreSQL 스키마는 변경되지 않습니다.
- `DATABASE_RUNTIME_ROLE`은 제거되며 runtime 역할은 보안 경계의 `app_runtime`으로 고정됩니다.
- API는 runtime 환경파일만 읽고, migration과 role provisioning은 별도 admin 환경파일만 읽습니다.
- migration은 `DATABASE_MIGRATION_URL`만, role provisioning은 관리자·업무·Auth DB URL만 요구합니다.
- `main`에는 검증된 변경만 PR로 병합하고 기술 상세는 목적별 브랜치 문서에 유지합니다.
