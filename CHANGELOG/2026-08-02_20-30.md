# 백엔드 실행 파일 구조 정리

## 변경 요약

- Fastify 백엔드를 인증, DB, HTTP route, 관리자 실행 스크립트 책임으로 분리했습니다.
- 백엔드 단위 테스트와 실제 PostgreSQL 통합 테스트를 `tests/backend/`로 모았습니다.
- 실행·테스트·파일 배치 기준을 `server/README.md`에 문서화했습니다.
- 현재 자체 백엔드와 이전 Supabase 기준선의 npm 명령 이름을 구분했습니다.

## 수정된 파일

- `server/auth/`: Better Auth 모델, 인스턴스와 HTTP 세션 처리
- `server/db/`: runtime DB pool, identity, 권한 경계와 actor 트랜잭션
- `server/routes/`: health와 platform HTTP API
- `server/scripts/`: migration과 DB role provisioning
- `tests/backend/`: 백엔드 단위·통합 테스트와 분리된 Vitest 설정
- `package.json`: 새 경로, `db:setup`, 단위·통합 테스트 명령 반영
- `.env.example`, `server/.env.example`: 프런트 공개 설정과 백엔드 비밀 설정 템플릿 분리
- `server/README.md`, `README.md`, `docs/SELF_HOSTED_BACKEND.md`, `AGENTS.md`: 구조·실행·협업 기준 갱신
- `db/migrations/0001_better_auth.sql`: Auth 모델 기준 파일 경로 주석 갱신

## 이유

프런트엔드와 백엔드가 한 저장소에 있는 동안에도 API 프로세스 진입점, 요청 처리 코드, DB 권한 코드와 관리자 명령을 혼동하지 않도록 하기 위해서입니다. 파괴적인 DB 통합 테스트가 일반 단위 테스트 명령으로 우발 실행되지 않도록 명령도 분리했습니다.

## 영향

- API URL과 DB 스키마는 변경되지 않습니다.
- API·DB 실행 명령은 루트 `.env.local`이 아니라 `server/.env.local`을 읽습니다.
- 기존 실행자는 새 npm script를 사용하므로 직접 참조하던 이전 `server/http/*`, `server/db/migrate.js`, `server/db/provision.js` 경로를 갱신해야 합니다.
- `npm run test:backend`는 이제 DB 없는 백엔드 단위 테스트만 실행합니다.
- 실제 DB 통합 테스트는 `npm run test:backend:integration`으로 명시적으로 실행합니다.
- 이전 Supabase CLI 명령은 `legacy:supabase:*` 이름으로만 남습니다.
