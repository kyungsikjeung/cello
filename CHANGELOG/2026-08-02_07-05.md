# 2차 리뷰: 복원 방어·렌더러 key·noindex

## 변경 요약

- 손상되거나 형태가 다른 localStorage 데이터(초안·공개본·버전 목록)로 admin 이 흰 화면으로 크래시하고 복원 버튼조차 누를 수 없던 문제를 복원 시 스키마 검증 + 기본값 대체 + 상태 표시줄 고지로 해소했다.
- 렌더러가 사용자 입력 콘텐츠(프로그램 라벨·설명 문구)를 React key 로 쓰던 것을 index 로 교체해, 편집자가 같은 라벨/문구를 입력할 때의 key 충돌을 제거했다.
- `admin.html`·`preview.html`에 `robots: noindex` 메타를 추가해 배포 시 관리 화면의 검색엔진 색인을 차단했다.
- 오탐 기각 기록: reduced-motion 사용자의 콘텐츠 미표시 의심은 `styles.css`의 `prefers-reduced-motion` 블록(opacity 1 !important)이 이미 커버해 버그가 아님을 확인했다.

## 변경 이유

localStorage 는 스키마 진화·수동 조작·부분 기록으로 언제든 형태가 어긋날 수 있는데, 복원 경로에 검증이 없어 단일 손상 값이 편집 화면 전체를 사용 불능으로 만들었다. 복구 UX 의 최소 조건은 "무엇이 잘못되어도 편집 화면은 뜬다"이다.

## 영향

- 초안이 손상되면 기본값으로 열리고 상태 표시줄에 대체 사실이 표시된다. 스키마를 통과하지 못하는 버전 항목은 목록에서 걸러진다.
- 렌더러 화면·모션 동작 변화 없음(키 교체는 렌더 결과 동일).
