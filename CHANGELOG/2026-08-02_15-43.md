# Supabase 로컬 개발 기반 추가

## 변경 요약

- Supabase CLI 2.111.0을 프로젝트 개발 의존성으로 고정했습니다.
- 로컬 Auth, PostgreSQL, Storage 검증에 사용할 Supabase 설정과 빈 seed 파일을 추가했습니다.
- 개발자가 같은 명령으로 로컬 스택을 시작, 확인, 초기화, 검사할 수 있도록 npm 스크립트를 추가했습니다.

## 수정된 파일

- `package.json`
- `package-lock.json`
- `supabase/.gitignore`
- `supabase/config.toml`
- `supabase/seed.sql`

## 이유

- PR #3의 인증, RLS, 공개/롤백 RPC를 클라우드 비용 없이 로컬에서 재현하고 검증하기 위한 기반이 필요했습니다.
- 로컬과 CI에서 사용할 CLI 버전을 동일하게 유지해야 검증 결과를 재현할 수 있습니다.

## 영향

- `npm install` 후 `npm run supabase:start` 등 표준화된 명령을 사용할 수 있습니다.
- 로컬 Storage 파일 제한은 파일당 15MiB이며, Auth 리다이렉트는 로컬 랜딩과 관리자 페이지로 제한됩니다.
- 이번 변경만으로 클라우드 Supabase 프로젝트가 생성되거나 연결되지는 않습니다.

## 검증 결과

- `npx supabase --version`: 2.111.0 확인.
- `npm ci`: 성공, 취약점 0건.
- `npm run build`: 성공.
- 이 목적 브랜치는 CMS 테스트 기반 PR보다 먼저 갈라져 `npm test` 스크립트가 아직 없습니다. PR #2 병합 후 CI 기준을 재적용해야 합니다.
- Docker Desktop 엔진 28.3.2가 최초 실행되는 것까지 확인했습니다.
- `supabase start`는 Docker Desktop 내부 containerd 저장소가 `read-only file system` 상태가 되어 이미지 다운로드 단계에서 실패했습니다.
- 비파괴 Docker Desktop 재시작 후에도 엔진이 `stopped` 상태여서 추가 초기화는 수행하지 않았습니다.
- 따라서 마이그레이션 적용, Auth, RLS, Storage, RPC 통합 테스트는 아직 완료되지 않았습니다.
