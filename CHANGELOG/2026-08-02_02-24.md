# 플랫폼 아키텍처 및 브랜치 운영 문서화

## 변경 요약

- 웹사이트 빌더 SaaS의 대안 아키텍처, 비용, 개발 리소스와 선택 기준을 문서화했다.
- `main`과 `CMSV2`의 역할을 명확히 하고 향후 기능 브랜치 분리 계획을 README 현황판에 추가한다.
- 실제 생성된 브랜치와 계획 단계 브랜치를 구분하고 각 GitHub URL을 표로 관리한다.

## 수정된 파일

- `README.md`
- `docs/PLATFORM_ARCHITECTURE_OPTIONS.md`
- `CHANGELOG/2026-08-02_02-24.md`

## 변경 이유

프로젝트가 단일 랜딩페이지에서 인증, 데이터베이스, 미디어, 공개, 도메인, 결제와 운영 기능을 포함하는 웹사이트 빌더 SaaS로 확장되었다. 안정 기준선인 `main`과 기능 개발 브랜치의 책임을 분리하고, 공급자 선택을 비용만이 아니라 개발량과 운영 위험까지 포함해 판단할 기준이 필요하다.

## 영향

- 실행 코드와 데이터 스키마는 변경하지 않는다.
- `main`은 안정 기준선과 전체 로드맵 문서를 유지한다.
- 기능 구현은 `CMSV2`에서 분기한 목적별 브랜치에서 진행하고 검증 후 `CMSV2`로 병합한다.

## 검증 결과

- `npm run build`: 통과. 기존 `heic2any` 청크 크기 경고는 남아 있으나 빌드 실패는 없다.
- 로컬 Markdown 링크 검사: 통과.
- `git diff --check`: 통과.
- 문서 전용 변경이므로 UI 브라우저 회귀 검증은 생략한다.
