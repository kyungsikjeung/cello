# 병합 후 기준선과 다음 개발 경로 정리

## 변경 요약

- PR #2와 PR #3이 병합된 실제 `main` 상태에 맞게 README 현황판을 갱신했습니다.
- Legacy `CMSV2`를 직접 병합하지 않고 최신 `main`에서 카테고리 변경만 이식하도록 명시했습니다.
- Supabase CLI 의존성 변경 시 DB migration·RLS CI도 다시 실행되도록 경로 필터를 보완했습니다.

## 수정된 파일

- `README.md`
- `.github/workflows/supabase-db.yml`
- `CHANGELOG/2026-08-02_18-53.md`

## 이유

- README가 이미 구현·검증된 Supabase migration과 RLS를 계획 상태로 잘못 표시하고 있었습니다.
- 오래된 `CMSV2`를 현재 `main`에 직접 병합하면 최신 CI와 Supabase 기준선이 삭제될 수 있습니다.
- `package.json`의 Supabase CLI 버전 변경도 DB CI의 검증 대상이어야 합니다.

## 영향

- 협업자가 현재 구현 범위와 다음 작업을 실제 코드 상태에 맞게 판단할 수 있습니다.
- 다음 개발은 최신 `main`에서 실제 Auth·워크스페이스 브랜치로 시작합니다.
- DB 도구 버전과 migration 테스트의 불일치를 CI에서 더 빨리 발견합니다.

## 검증 결과

- PR #2 head와 `main` 병합 결과의 Git tree가 동일함을 확인했습니다.
- 병합 후 GitHub Actions `test-and-build`가 성공했습니다.
- 기존 Supabase migration·lint·47개 DB 테스트 실행이 성공했습니다.
- 로컬 `npm run build`가 성공했습니다.
- 로컬 `npm test`는 코드 실패가 아니라 C: 여유 공간 부족으로 새 devDependency를 설치하지 못해 재실행하지 않았습니다. 원격 `npm ci` 환경에서는 31개 테스트가 통과했습니다.
