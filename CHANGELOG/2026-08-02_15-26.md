# 서버 프로젝트 역할명을 reviewer로 통일

## 변경 요약

- 첫 Supabase migration의 읽기 전용 역할을 `viewer`에서 `reviewer`로 변경했다.
- 프로젝트·문서·Release·미디어 조회 정책의 허용 역할 배열도 `reviewer`로 통일했다.

## 수정된 파일

- `supabase/migrations/20260802120000_init.sql`
- `CHANGELOG/2026-08-02_15-26.md`

## 이유

Local MVP의 `viewer`는 화면 검증용 이름이며, `docs/CLOUD_MVP.md`와 `docs/LOCAL_FIRST_BACKEND.md`는 서버 역할을 `owner`, `editor`, `reviewer`로 통일하고 Local `viewer`를 `reviewer`로 매핑하도록 정의한다. migration이 이 계약과 달라 실제 Auth 연결 전에 바로잡았다.

## 영향

- 서버 권한 계약과 문서의 역할명이 일치한다.
- Local 데모 계정의 `viewer`는 클라우드 전환 어댑터에서 `reviewer`로 매핑해야 한다.
- 이미 적용된 운영 migration은 없으므로 enum 값 변경 migration을 별도로 만들 필요가 없다.

## 검증 결과

- migration의 `viewer` 잔여 문자열 없음.
- `git diff --check`: 통과.
- Docker CLI는 설치되어 있으나 Docker Engine이 실행 중이지 않아 Supabase Local migration·RLS 통합 검증은 미실행이다.
