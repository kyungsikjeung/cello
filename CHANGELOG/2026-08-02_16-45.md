# Supabase 권한·Release 통합 테스트 추가

## 변경 요약

- Supabase Local과 GitHub Actions에서 실행할 pgTAP 데이터베이스 통합 테스트를 추가했습니다.
- owner, editor, reviewer와 교차 프로젝트 사용자의 RLS 경계를 검증합니다.
- revision 충돌, 공개, 공개 실패의 원자성, 롤백, 직접 쓰기 차단과 Release 불변성을 검증합니다.
- Supabase CLI 2.111.0을 고정한 CI에서 migration, lint, 47개 권한 검증을 순서대로 실행합니다.

## 수정된 파일

- `supabase/tests/database/platform_rls.test.sql`
- `.github/workflows/supabase-db.yml`

## 이유

- SQL migration 적용 성공만으로는 실제 JWT 사용자별 접근 통제와 RPC 경계를 증명할 수 없습니다.
- PR #3을 Ready로 전환하기 전에 재현 가능한 서버 권한 회귀 테스트가 필요합니다.

## 영향

- `supabase test db`로 핵심 백엔드 경계를 반복 검증할 수 있습니다.
- 테스트 데이터는 트랜잭션 안에서 생성되고 마지막에 롤백되므로 로컬 DB에 남지 않습니다.

## 검증 결과

- WSL2 Ubuntu에 Docker Engine 29.7.1과 Docker Compose 5.3.1 설치 완료.
- WSL 재기동 후 Docker 서비스 자동 시작과 `hello-world` 실행 성공.
- Supabase CLI 2.111.0 Linux 패키지의 SHA-256을 검증하고 설치 완료.
- 최소 Postgres 컨테이너가 healthy 상태로 시작되는 것까지 확인했습니다.
- C: 공간 부족으로 WSL 파일시스템이 일시적으로 읽기 전용 전환되어, 테스트 이미지를 제거하고 추가 실행을 중단했습니다.
- 로컬 반복 실행은 C: 공간 회수 후 다시 확인해야 합니다.
- 로컬 디스크와 분리된 GitHub Actions에서 `db reset`, `db lint`, `test db`를 실행하도록 구성했습니다.
