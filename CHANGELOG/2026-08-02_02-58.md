# 비용 우선 Local-first 백엔드 아키텍처 결정

## 변경 요약

- 백엔드 기본 경로를 `Supabase Local → Hosted Free Preview → 첫 유료 고객부터 Pro`로 확정했다.
- 현재 Vite 멀티페이지 앱의 기본 배포 후보를 Cloudflare Workers Static Assets로 조정했다.
- Vercel은 상용 Pro가 필요한 SEO·Next.js·Preview 대안으로, R2는 미디어 사용량 증가 이후 대안으로 이동했다.
- 무료 Preview와 상용 운영의 경계를 비용·백업·가용성 기준으로 명시했다.
- 현재 DB 초안의 공개 권한·불변 Release·워크스페이스·Storage 정책 누락을 배포 전 P0로 표시했다.

## 변경 이유

클라우드 계정과 유료 인프라를 먼저 준비하지 않고도 실제 Auth·PostgreSQL/RLS·Storage 계약을 로컬에서 검증할 수 있어야 한다. 동시에 무료 서비스를 상용 운영으로 오해하거나, 개발용 로컬 스택을 인터넷에 공개하는 위험을 막을 기준이 필요했다.

## 영향

- 다음 백엔드 MVP는 Supabase CLI, migration, seed와 교차 프로젝트 RLS 테스트부터 시작한다.
- Hosted Supabase와 Cloudflare 계정은 로컬 수용 기준을 통과하기 전까지 즉시 차단 요소가 아니다.
- 첫 유료 고객 전에는 Supabase Pro, 백업·복원 훈련과 비용 알림이 출시 게이트가 된다.
- `supabase/schema.sql`은 배포 파일이 아니라 migration 재설계 전 읽기용 초안으로 취급한다.
- 런타임 UI와 데이터 동작은 변경하지 않았다.

## 검증 결과

- `npm run build`: 통과 — Vite 8.2.0, 112개 모듈 변환
- 멀티페이지 산출물: `index.html`, `admin.html`, `preview.html` 생성 확인
- 문서 내부 상대 링크: 통과 — 변경 문서 6개 검사
- Markdown 코드 펜스: 통과 — 변경 문서 6개 검사
- 최종 동료 검토: P0 없음 — 장기 실행 명령을 별도 터미널로 분리하고 DB·Storage 객체 백업을 별도 출시 게이트로 보완
- Supabase Local 실행: 미실행 — Docker Engine과 프로젝트 로컬 CLI 구성 전
- Cloudflare 배포: 미실행 — Wrangler 설정과 계정 연결 전
- 기존 경고: `heic2any` 청크가 500kB를 초과하며 이번 문서 변경으로 새로 발생한 오류는 아님
